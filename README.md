## 9929、CN2 GIA、CMIN2 分别是谁家的线路

国内三家运营商各有一条“VIP 骨干”，专门跑对延迟和丢包敏感的国际流量：

- 联通：CUII（China Unicom International Infrastructure），ASN 是 **AS9929**；联通国际段是 AS10099（China Unicom Global）
- 电信：CN2 GIA，ASN 是 **AS4809**
- 移动：CMIN2，ASN 是 **AS58807**

普通国际出口是另一回事，电信 163 骨干 AS4134、联通 163 骨干 AS4837，价格便宜，晚高峰大家一起挤。

英国机房接 9929 的典型路径是：伦敦 → 联通国际 AS10099 → 德国法兰克福联通 POP → 横跨欧亚回国 → 落地国内联通 CUII。全程不经过美国，回程能压到 160ms 上下。

接 CN2 GIA 的路径类似，只是中间换成电信的节点和 59.43 段地址，最终落在电信骨干上。

这里有个现实问题：英国机房接 9929 的比接 CN2 GIA 的多，因为联通在欧洲的 POP 比电信密集，商家接起来成本更低。所以市面上“英国优化线路 VPS”绝大多数是联通 9929 方案，电信 CN2 GIA 的英国节点反而是少数。AkkoCloud 伦敦这条属于后者。

**这条信息怎么用**：回程走谁家的骨干，谁家的用户体验最好。你家是联通宽带，9929 回程的节点对你最顺；你家是电信宽带，CN2 GIA 回程的节点对你最顺。买之前先看自己家宽带是哪家，比看商家宣传页上的“三网优化”有用。

## 去程和回程是两段路，60ms 的差距出在去程

很多人以为“回程走 9929 就万事大吉”，实际体验不是这样。

以公开测评里的一台英国 9929 节点为例：

- **联通**：去程 AS10099 直达法兰克福转伦敦，回程 AS9929，平均 163ms
- **移动**：去程 CMI 直连伦敦，平均 190ms
- **电信**：去程从国内骨干 → 美西圣何塞电信 POP → telia 转美东纽约 → 跨大西洋到伦敦，回程才走 9929，平均 **235ms**

电信这 235ms 里有 70ms 是去程绕美国绕出来的。回程再优化也补不回来，因为数据包去的时候已经多飞了一趟。

AkkoCloud 伦敦这条线的公开测评给的是另一组数字：三网平均 167ms，其中电信 169ms、联通 167ms、移动 163ms。三家几乎贴在一起。测评记录的去程路由是电信走 59.43 的 CN2 段、联通走 AS4837、移动走 CMI，三网都从北京出口经德国落地伦敦，没有绕美。

两组数字放在一起，结论很清楚：**英国节点上电信用户体验差，八成是去程绕了美国；去程走 CN2 的节点，电信能追回 60ms 左右。**

这组数据来自第三方测评，测试时间未标注、测试机也不同，不能拿去精确比较，只能看量级。但它解释了一个买之前必须搞明白的事：商家说“三网优化”，你得追问是去程优化还是只有回程优化。

这张表能回答两个问题。

**第一，160ms 是英国节点的地板。** 物理距离摆在那，谁家也压不到 100ms 以内。看到宣传“英国节点 100ms 以内”的，基本可以关掉页面。

**第二，220ms 以上的英国节点，多半走的是普通国际 BGP。** 这类节点便宜、流量大，但晚高峰丢包和抖动控制不了。

**所以英国节点不适合干什么：** 建站。国内访问 200ms 上下，WordPress 后台点一下等半秒，客户打开首页要转圈。纯静态站挂 CDN 能缓解一部分，动态站体验照样差。公开测评里对英国住宅 IP 节点的建站建议也是“搭配中转使用”，这条对任何英国节点都成立。

**适合干什么：** 做欧洲区的落地节点、给国内访问欧洲服务做中转、跑不需要低延迟的常驻任务、拿一个英国 IP 处理只在英国区可用的服务。

## 双 ISP 住宅 IP：AkkoCloud 没有，这是它最硬的一条限制

“英国双 ISP 住宅 IP”这两年成了卖点，很多人冲着这个词下单，但没搞清楚它解决的是什么问题。

住宅 IP 的价值在风控，不在速度。普通机房 IP 的 ASN 注册在 hosting 公司名下，TikTok、Netflix、BBC iPlayer 这类平台一查就知道你不是本地家庭用户，账号进灰区、触发代理检测、直接拒绝访问，都从这里来。住宅 IP 的段注册在英国本地宽带运营商名下，平台看到的是一个普通英国网民。

“双 ISP”是更进一步：IPv4 和 IPv6 分别注册在不同的英国 ISP 名下。公开测评里某英国节点的 IPv6 走的是 Catixs Ltd / AS48266，属于这种配置。

**AkkoCloud 伦敦这条线不是住宅 IP。** 第三方测评明确写了这一点，也建议需要家宽住宅 IP 的人另找。这意味着：

- 想跑英区 TikTok 账号矩阵的，这条线不合适
- 要看 BBC iPlayer 的，机房 IP 通常被直接拒绝
- 做 Amazon UK、Shopify 英国本土店登录操作的，风控通过率不如住宅 IP
- 只是需要一个英国 IP 访问普通网站、注册英国区服务、跑 API 中转的，机房 IP 完全够用

还有一件前排文章基本不提的事：**住宅 IP 段会被运营商收回。** 2024 年底，某英国住宅 IP 商家使用的 Vorboss 段就发生过 IP 被运营商收回的事故，用户被迫换 IP，商家后来换成 Sky 天空电讯的新 A 段并做了补偿。

这条对所有人的意义是一样的：IP 属性不是永久资产，住宅 IP 尤其如此，因为它挂在别人的运营商名下。跑账号、跑店铺这类和 IP 绑定的业务，必须准备好备用节点和迁移方案，别把全部业务压在一个 IP 段上。
